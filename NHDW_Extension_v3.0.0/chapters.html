NHDW · EXPERIMENTAL

Chapter collection

Collect chapters from a title or save an open chapter. Works only on compatible, normally accessible HTTPS pages; it cannot bypass login, Premium access, challenges or browser cross-origin rules.

Connecting to the selected tab…

01

Find chapters

Open a title in the source tab, then scan. If its list is paginated, navigate that tab to each list page and scan again. Only observed links are collected; check the full selection yourself.

Scan list pages in their displayed order. No numeric sorting, hidden pages, related titles or site-provided batch links are guessed.

02

Inspect the selected readers

Supply a selector that matches only ordered page images. Static chapter HTML is inspected for title batches; JavaScript-only readers may not work. “Use open chapter” inspects the already-rendered page. The counts are discovered references, not proof that the full chapter or the intended server was found.

If image names are random hashes (e.g. a1B2c3D4e5F6g7H8-mini.jpg), file numbers cannot order them: use the page links. A strategy that cannot number every page refuses instead of guessing, and the review shows the resolved order to check.

Top-down / scroll readers list every page as an image in DOM order, so that order is the page order even when the file names are random hashes. If a reader only loads near the viewport, open one chapter with “Use open chapter”, press Load all pages (top-down) (it scrolls the source tab), then inspect. A page count the reader advertises is compared with what was found.

03

Save

If a usable site-provided batch exists for your selection, use that first. This action is a separate, explicitly chosen page-reader workflow; it does not discover or use batch mirrors.

CBZ chapters get a minimal ComicInfo.xml (series, chapter, page count) so comic readers show a title. One archive per chapter; keep this page and the source tab open. No history or credentials are stored by this tool. Image signatures are checked, not full image decoding. Throttling (429) or access denial (401/403) always stops the run and never produces a salvaged file.
